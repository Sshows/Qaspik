# Qaspik

Панель расчёта цен с тестовым каталогом, проверкой формата NTIN и обработчиком вебхука Telegram. Локальная версия хранит демоданные в памяти. Публичная версия показывает их в режиме просмотра.

## Локальный запуск

```bash
npm ci
npm test
npm start
```

Откройте [панель товаров](http://127.0.0.1:3000/products). В таблице выберите товар, откройте список продавцов и задайте цену конкурента. Результат расчёта появится в демо-журнале. Лимит 3–4 устройств также проверяется в демо. Состояние сбрасывается при перезапуске процесса.

## Пилот для одного магазина

Тариф пилота — 10 000 ₸ в месяц. Оператор вручную задаёт дату окончания доступа `subscription.expiresAt` в UTC. При `subscription.enabled: false` или истечении срока воркер прекращает запись и завершает `watch`. Оплата и удалённое отключение пока не подключены. Для немедленной остановки на компьютере нажмите Ctrl+C.

Скопируйте учебные файлы в отдельную папку. Обновите время наблюдений **только для учебного примера**, чтобы сработал расчёт.

```powershell
Copy-Item -Recurse examples/pilot .qaspik-demo-pilot
$obs = '.qaspik-demo-pilot/observations.json'
$snapshot = Get-Content -Raw -LiteralPath $obs | ConvertFrom-Json
foreach ($offer in $snapshot.offers) { $offer.observedAt = [DateTime]::UtcNow.ToString('yyyy-MM-ddTHH:mm:ssZ') }
$snapshot | ConvertTo-Json -Depth 5 | Set-Content -Encoding utf8 -LiteralPath $obs
node scripts/kaspi-pilot.js plan .qaspik-demo-pilot
node scripts/kaspi-pilot.js apply .qaspik-demo-pilot
```

План покажет `25 390 ₸` для Алматы на первом товаре и `12 079 ₸` для второго. Команда `plan` только показывает расчёт. `apply` один раз меняет цены в рабочей копии XML. `watch` делает это автоматически, проверяя входные файлы раз в минуту.

Для магазина используйте отдельную папку с тремя файлами.

- `catalog.xml` — рабочая копия полного исходного прайса этого продавца. Сохраните оригинал отдельно. Воркер меняет только цифры выбранной цены. Сверьте с кабинетом полноту каталога и актуальность остатков. Ведение остатков должно быть согласовано с тем, кто обновляет рабочий XML.
- `pilot.json` — идентификатор из `<merchantid>`, срок доступа и правила для выбранных SKU. Для городской цены укажите `cityId`, для общей оставьте поле пустым, то есть удалите его. `minPrice` задаёт нижний порог, `standardStep` — обычный шаг, `nearFloorWindow` — расстояние от цены конкурента до порога, при котором шаг становится 1 ₸. `maxPrice` при необходимости ограничивает новую цену сверху. Если конкурент по цене дошёл до порога или ниже, цена остаётся прежней.
- `observations.json` — свежие цены других продавцов по тому же SKU и городу с фактическим временем наблюдения `observedAt`. Сейчас этот файл заполняет оператор или согласованный внешний источник. Пропущенные и просроченные наблюдения оставляют цену прежней.

После проверки результата продавец размещает полный рабочий XML на своём HTTPS-сервере и один раз добавляет его ссылку в автоматическую загрузку прайса Kaspi. Публикация файла на сервер и проверка применения цены в кабинете выполняются отдельно. После остановки воркера последняя версия XML остаётся на сервере. Чтобы прекратить загрузку, владелец отключает ссылку в кабинете Kaspi. [Автоматическая загрузка прайса](https://guide.kaspi.kz/partner/ru/shop/goods/price_list/q3251)

## Kaspi и Supabase

Официальный способ автоматического обновления цен использует полный XML-прайс-лист, указанный продавцом в кабинете. Интеграция магазина через Qaspik и запись цен отключены. В локальном запуске `QASPIK_KASPI_CATALOG_READ=1` включает опциональную диагностику чтения каталога через `POST /api/store/sync/trigger`. Диагностика не меняет цены или остатки. [Инструкция Kaspi по прайс-листу](https://guide.kaspi.kz/partner/ru/shop/goods/price_list/q2962)

Демо использует отдельное состояние в памяти. Перед подключением рабочих данных нужно ограничить доступ к таблицам Supabase и привязать запросы к проверенному владельцу магазина. [Документация Supabase по RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

## НКТ

NTIN присваивает Национальный каталог товаров. Формат `02` и 11 цифр проверяется локально. Такой результат отмечается как «Требуется проверка в НКТ» до подтверждения карточки. Подать заявку можно в [Национальном каталоге товаров](https://nationalcatalog.kz/). Автоматический поиск и подача требуют [доступа к API НКТ](https://nationalcatalog.kz/gwp/docs).

## Вебхук Telegram

Для проверки текущего состояния `@Qaspik_bot` укажите `TELEGRAM_BOT_TOKEN` в локальном `.env` и выполните команду.

```bash
node scripts/telegram-webhook.js status
```

Для регистрации на Vercel задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` в переменных production. После деплоя задайте те же значения в локальном `.env`, укажите HTTPS-адрес маршрута `/api/telegram/webhook` в `TELEGRAM_WEBHOOK_URL` и выполните команду.

```bash
node scripts/telegram-webhook.js set
```

Вебхук проверяет заголовок с секретом от Telegram. Бот отвечает в личных чатах на `/start` и `/help`. Для уведомлений о ценах ещё нужны подтверждённые изменения в Kaspi и проверенная привязка чата к магазину. [Документация Telegram Bot API](https://core.telegram.org/bots/api#setwebhook)
